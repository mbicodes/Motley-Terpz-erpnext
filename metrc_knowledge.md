## 1. How Metrc auth works

- Base URL depends on environment:
  - **CA Sandbox (test):** `https://sandbox-api-ca.metrc.com`
  - **CA Production (live):** `https://api-ca.metrc.com`
- Every request: HTTP Basic auth, **username = vendor/integrator key**, **password =
  user API key**. Plus `?licenseNumber=<LIC>` on most calls.
- The app's client does exactly this: `metrc/client.py` → `session.auth = (integrator_key,
  user_key)`. `metrc/config.py` resolves base URL + keys.
- **`GET /facilities/v2`** is the cheapest connectivity/auth test (no licenseNumber needed).
  200 = keys valid; 401 = key mismatch.

## 2. Keys & where they're stored (do NOT hardcode secrets)

- **`Metrc Settings`** (Single) → field `integrator_key` (Password/encrypted) = vendor key.
  Facilities child table (`Metrc Facility`) → `user_key` (Password) per license.
- **`Metrc Config`** (Single, new — see §8) → `base_url` + `api_key` (vendor). Its Test
  Connection reuses the user key from Metrc Settings.
- Keys are encrypted in the site `__Auth` table — **not in code/JSON**, so they don't
  travel via git. Read them with `doc.get_password("integrator_key")` /
  `frappe.utils.password.get_decrypted_password("Metrc Facility", row, "user_key")`.
- Key names in Metrc Connect: **"Osama"** = CA **Sandbox** vendor key; **"Live"** = CA
  **Production** vendor key. The sandbox **user** key is the public CA sandbox demo user
  key (`mcHaLEtx…`). Production user keys must be generated by the client's **Metrc
  Industry Admin** in the production Metrc UI — they do not exist yet.

## 3. The 3-level permission model (memorise this — explains every 401)

Per the certification workbook's Permissions sheet, access has **three layers**:
1. **Facility permissions** — set by the **state/Metrc** on the facility. Visible in
   `GET /facilities/v2` under `FacilityType` flags (e.g. `CanCreateOpeningBalancePlantBatches`,
   `CanCreateOpeningBalancePackages`, `CanClonePlantBatches`). You cannot change these.
2. **Vendor-key permissions** — the endpoint scopes granted to your integrator
   registration/deployment (Metrc Connect → Keys → the key's "Read-Write Permissions").
   Requested via the evaluation submission / Metrc API support.
3. **User-key permissions** — what the Metrc employee whose key you use can do; set by the
   client's Industry Admin in the Metrc UI.

A **401** = level 2 or 3 mismatch. A capability flag `false` in `GET /facilities/v2` = level 1.

## 4. Which sandbox licenses have data (for testing writes)

`GET /facilities/v2` lists ~21 CA sandbox facilities. Key ones:
- **`C12-1000001-LIC`** (Microbusiness 01) — **has 11 flowering plants + an active plant
  batch**. This is the license to use for the whole cultivation chain (you need existing
  plants to clone from). Location type "Cultivation" / plants sit in locations like "A-1".
- **`A12-0000015-LIC`** (Cannabis Microbusiness) — 360 strains, 44 locations, 1500+ tags,
  but **0 plants** (can't clone from nothing).
- **`CML17-0000001`** (Cannabis Farms) — 0 strains/locations initially; has one universal
  "Default Location Type" (ForPlantBatches/Plants/Harvests/Packages all true). Good for the
  master-data (Locations/Strains/Items) tasks.
- All grow facilities have `CanCreateOpeningBalancePlantBatches = false` and
  `CanCreateOpeningBalancePackages = false` → opening-balance creates are blocked everywhere.

## 5. What works vs what's blocked (verified live)

### ✅ Works (write, real records created)
- **Locations / Strains / Items** — POST create, PUT update, GET view.
- **Plants:** `plants/v2/plantings` (clone from a mother plant), `plants/v2/location`
  (move), `plants/v2/manicure`, `plants/v2/harvest`, `plants/v2` DELETE (destroy),
  `plants/v2/plantbatch/packages`.
- **Plant Batches:** `plantbatches/v2/packages`, `plantbatches/v2/growthphase`,
  `plantbatches/v2` DELETE.
- **Harvests:** `harvests/v2/packages`, `harvests/v2/waste`, `harvests/v2/finish`,
  `harvests/v2/unfinish`.
- **Packages:** `packages/v2` (derived: repackage/split/combine), `packages/v2/item`,
  `packages/v2/adjust`, `packages/v2/finish`.
- **Transfers:** GET incoming/outgoing/rejected, `transfers/v2/{id}/deliveries`,
  `transfers/v2/delivery/{id}/packages`; **transfer templates** POST/PUT/GET
  `transfers/v2/templates/outgoing` (+ `.../outgoing/{id}/deliveries`).
- **Sales:** `sales/v2/receipts` (authorized). **Lab tests:** authorized.

### 🔒 Blocked (Metrc-side, not code)
- **`POST /plantbatches/v2/plantings`** (create batch from seed / opening balance) →
  facility flag `CanCreateOpeningBalancePlantBatches = false` on ALL sandbox grow
  facilities. **Workaround:** create batches via `plants/v2/plantings` (clone from a
  mother plant), which works.
- **`POST /transfers/v2/external/incoming`** (+ PUT/DELETE) → **401 on every license** =
  vendor-key scope not granted. Marked "Optional" in the Permissions sheet. Request from
  Metrc if the business needs external-incoming transfers. **Initiating/receiving licensed
  transfers between licensees is not an API action either** — `transfers/v2/incoming` and
  `/outgoing` are GET-only (405 on writes); that lifecycle is done in the Metrc portal by
  design. `plantbatches/v2/plantings` and `packages/v2` opening-balance are the only
  facility-flag blocks; everything else authenticates.

## 6. Endpoint schema gotchas (these took trial-and-error — save yourself the pain)

- **`POST /plants/v2/plantings`** (this sandbox requires plant-batch tags):
  `PlantLabel` = an **existing plant's tag** (the mother you clone from) — NOT a fresh
  available tag; `PlantBatchName` = an **available plant tag** (facility requires batch
  tags, so free text is rejected). Plus `PlantBatchType` ("Clone"/"Seed"), `PlantCount`,
  `LocationName`, `StrainName`, `PatientLicenseNumber`, `ActualDate` (must be ≤ today).
- **`PUT /plants/v2/harvest`**: `{Plant, Weight, UnitOfWeight:"Grams", DryingLocation,
  HarvestName, ActualDate}` — field is `DryingLocation` (not `DryingLocationName`).
- **`DELETE /plants/v2`** (destroy): needs `WasteReasonName` (from
  `GET /plants/v2/waste/reasons`), `WasteMethodName` (valid values from `GET /wastemethods/v2`
  — e.g. "Compost", NOT "Grinder"), `WasteWeight`, `WasteUnitOfMeasure:"Grams"`, `ReasonNote`.
- **`POST /harvests/v2/packages`**: needs an **`Ingredients`** array
  `[{HarvestName, Weight, UnitOfWeight}]` — error "Package require at least one Ingredient"
  if omitted. Plus `Tag` (available package tag), `Item`, `Location`, `UnitOfWeight`.
- **Package endpoints** (`packages/v2/item|adjust|finish|unfinish`): the field is **`Label`**
  (the package tag), NOT `PackageLabel`. Finish needs the package emptied first (adjust to 0).
- **`POST /plantbatches/v2/growthphase`**: `GrowthPhase:"Flowering"` — "Vegetative" is
  rejected if `CanTrackVegetativePlants = false`.
- **Transfer templates** (`POST /transfers/v2/templates/outgoing`): full body with
  `Name`, `TransporterFacilityLicenseNumber`, `Destinations:[{RecipientLicenseNumber,
  TransferTypeName:"Transfer", PlannedRoute, EstimatedDeparture/ArrivalDateTime,
  GrossWeight, GrossUnitOfWeightName, Transporters:[{…driver/vehicle…}],
  Packages:[{PackageLabel, WholesalePrice:null}]}]}`. Use `TransferTypeName:"Transfer"` and
  `WholesalePrice:null` unless the type is a wholesale type (else "Wholesale Price is not
  associated with the Transfer Type"). The **template deliveries** GET is
  `GET /transfers/v2/templates/outgoing/{id}/deliveries` (note the `/outgoing/` segment).
- **Dry-run gate:** `metrc/client.py` short-circuits any non-GET when
  `config.is_dry_run()` is true — logs "DRY RUN - not transmitted" and returns None. Turn
  off dry_run (or use raw `requests`) to actually write during testing.

## 7. The Metrc Config doctype (new — added this session)

- `Metrc Config` (Single, module Cannabis Management): `base_url`, `api_key` (vendor,
  encrypted), **Test Connection** button, and a CEO-facing **capability overview** HTML.
- `test_connection()` = read-only `GET /facilities/v2` (safe against production). Uses the
  api_key here as vendor + the user key from Metrc Settings.
- Default `base_url` = sandbox. **Stage stays sandbox**; on production set it to
  `https://api-ca.metrc.com` + the Live key.
- ⚠️ **gitignore gotcha:** `.git/info/exclude` on the stage bench has
  `cannabis_management/cannabis_management/doctype/metrc_*/` — it hides ANY new `metrc_*`
  doctype from git. Had to `git add -f`. Check the live bench's exclude too.

  `sudo chown -R frappeuser:frappeuser .git`. Run git/deploys as `frappeuser`, not root.
